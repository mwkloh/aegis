# AEGIS — Improvement System

**Status:** Canonical  
**Scope:** Reflection and Human-Governed Improvement  

---

## Purpose

The AEGIS improvement system exists to **reduce friction, increase reliability, and improve long-term performance** without allowing autonomous self-modification.

AEGIS improves by observing execution, reflecting on outcomes, and proposing bounded changes that require explicit human approval.

---

## Core Rules

1. Runtime execution MUST NOT modify itself.
2. All improvement actions are **proposal-first**.
3. Human approval is required before any change.
4. All changes must be auditable and reversible.
5. Improvement logic always runs out-of-band.

---

## Improvement Lifecycle

```
Execution → Events → Patterns → Proposals → Decisions → Coding Tasks → Review → Merge
```

Each step produces persistent artifacts.

---

## What Improvement Is

✅ Identifying recurring failures  
✅ Reducing tool friction  
✅ Refining skills and memory retrieval  
✅ Improving prompts and scaffolding

---

## What Improvement Is Not

❌ Runtime self-modification  
❌ Autonomous deployment  
❌ Preference or identity drift  
❌ Silent behavioral change
